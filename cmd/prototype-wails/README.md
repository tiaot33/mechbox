## 运行

```sh
# 桌面窗口(Wails v2,无需安装 wails CLI)
go run -tags desktop,production ./cmd/prototype-wails

# 浏览器
go run ./cmd/prototype-wails -browser    # 打开 http://localhost:34115/
```

在本仓库的 git worktree 里运行时，前面加 `GOWORK=off`(worktree 里没有被 gitignore 的 go.work,Go 会用上主检出的那份)。

底部深色胶囊右侧的 `Agent ×2 / ×15` 在 v1 的 2 个 Agent 与 15 个 Agent(除 Claude Code / Codex 外均为假设)之间切换，用来检验布局能否随 Agent 数增长。

## 变体 A · 设计稿三栏(从技能出发)

- **左栏**:筛选——所有技能 / 有可用更新 / 集合(按来源)/ 组。
- **中间**:技能卡片(或列表)。点卡片打开右侧详情抽屉：元数据、组成员、已激活作用域列表 +"激活到 [地方] [Agent]"、SKILL.md、版本历史。
- **右栏**:作用域——全局与每个已登记项目下，只展开用到的 Agent,其余折进"+ 其他 N 个 Agent";项目行折叠时用小图标显示在用的 Agent。
- **顶栏(统一工具栏)**:左 = 侧栏开关 + 当前筛选与数量;中 = 作用域胶囊(▾ 弹层按地方分组、只列在用的 Agent,× 清除);右 = 搜索(⌘K)、仅已激活、列表 / 卡片、右栏开关。
- **选中作用域后**:卡片上出现该作用域的独立激活开关；列表顶部出现作用域摘要——投影目录、已激活 / 需重写数量、"全部重写",以及每个组的整组开关(显示经由本组激活的成员数)。
- **拖放**:
  - 技能卡片 → 右栏作用域 = 独立激活(已经由组激活时追加独立来源);
  - 技能卡片 → 左栏组 = 加入该组(不自动投影);
  - 左栏组 → 右栏作用域 = 整组激活;
  - 拖到折叠的项目行或"其他 N 个 Agent"上停 0.5 秒自动展开;右栏隐藏时开始拖动会自动显示;
  - 拖动中所有可放目标显示虚线框，已在的目标变灰并标"已在",组不能拖到组上。

## 已排除

- **C 矩阵总览**(技能 × 作用域网格,2026-09-23 排除):列数 = (全局 + 已登记项目数) × Agent 数,v1 只有两个 Agent 时还能排开，将来接入十几种 Coding Agent 后横向完全放不下。结论:Agent 不能作为界面上的一个固定维度平铺展开，布局要能随 Agent 数量增长而不改变结构。代码在提交 `f23e7dd`。
- **B 作用域优先**(左栏选地方、顶部标签选 Agent,主区是该作用域的组 / 已激活 / 从库中添加,2026-09-23 排除):用户打开软件多半是想着某个技能，再从技能出发调整它激活到哪些作用域;数据模型也以技能为中心，作用域只是投影目标。A 的顶栏作用域胶囊 +"仅已激活"已覆盖 B 的主要用途,B 独有的作用域健康概览和整组开关已并入 A 的作用域摘要。代码在提交 `9d9dd3c`。
