# 桌面端

Mechbox 的桌面端：Wails v3 应用，Go 进程直接持有技能库（Library），React 前端经 Wails 绑定调用它（ADR 0008）。macOS 一等支持，Windows / Linux 只保证能编译。

以下命令都在 `cmd/desktop/` 目录下执行。

## 功能

桌面端覆盖技能库(Library)的全部功能，界面按 UI 原型变体 A 组织：

## 开发

```sh
wails3 dev
```

它会生成绑定、启动 Vite 开发服务器（端口 9245），再编译并打开开发版应用 `bin/mechbox.dev.app`。用 `wails3 task dev`、`dev:test-db`、`dev:seeded` 启动时，Vite 每次自动选一个空闲端口；设了 `WAILS_VITE_PORT` 时用它。

- 改前端（`frontend/src/`）：窗口热更新，不重启。
- 改 `cmd/desktop/` 下的 Go 代码：自动重新生成绑定、重新编译并重启应用。
- 改 `internal/library/`：不在监听范围内（监听根目录是 `cmd/desktop/`），要 Ctrl-C 后重新 `wails3 dev`。
- 按 Ctrl-C 结束。如果异常退出后再启动报 `address already in use`，是上次的 Vite 还占着端口：`lsof -ti tcp:9245 | xargs kill`。

开发版默认打开的是**真实技能库**（见下文“运行时行为”），安装操作也会写进真实的 Agent 目录。

**用测试数据库调试。** 设置(GitHub 令牌、同步设置、应用设置)都存在数据库里，不读环境变量，所以本地调试的口子只开在「打开哪个数据库」上：设了 `MECHBOX_LIBRARY=<路径>` 时桌面端打开那个文件，不打开真实技能库。它不覆盖任何一项设置，换一个数据库就是换一整套设置，不会和真实技能库的混在一起。固定的测试数据库是 `.dev/library.db`(已在 `.gitignore` 里),用它启动：

```sh
wails3 task dev:test-db
```

第一次打开时在设置页填好令牌、同步设置(同步建议填测试用的存储桶或另一个文件夹，免得拉回时选错、或推送挤掉真实的旧备份),之后每次启动都在。想从头来就删掉 `.dev/`。也可以直接指定别的数据库：`MECHBOX_LIBRARY=/tmp/other.db wails3 dev`。「关于」里显示的数据库位置就是现在打开的那个。

这样只隔离了数据库：`~/.gitconfig`、`~/.ssh`、`gh` 的登录照常可用，调试 Git、GitHub 来源不受影响;但 Agent 目录仍按真实 `HOME` 算，安装会写进真实的 `~/.claude/skills` 等目录。要连安装也隔离，就再给一个临时 `HOME`(技能库位置和 Agent 目录都从 `HOME` 推导;Go 缓存也默认跟着 `HOME` 走，一并指回原处，免得重新下载依赖):

```sh
HOME=/tmp/skills-dev GOMODCACHE=$(go env GOMODCACHE) GOCACHE=$(go env GOCACHE) wails3 dev
```

**调试新版本。** 开发版与 server 模式不检查 Mechbox 的新版本(左栏不出现新版本，「关于」里写着这个版本不检查);设了 `MECHBOX_RELEASE_FEED=<地址>` 时读它，格式同每个版本附带的 `release.json`(GitHub releases 接口返回内容里的 `tag_name`、`body`、`html_url`、`published_at`、`assets`),用本地的假发布页看界面。

**用开发数据调试。** 在 app 里看界面、验证改动时，用 `wails3 task dev:seed` 生成的开发数据，再用 `wails3 task dev:seeded` 启动，不用每次自己造技能。数据里有什么、怎样重置，见 [测试改动](../../docs/testing.md) 的「在 app 里验证界面」。

## 构建与打包

```sh
wails3 build     # 只编译二进制：bin/mechbox
wails3 package   # 打成 macOS 应用：bin/mechbox.app（ad-hoc 签名）
open bin/mechbox.app
```

`bin/` 不入库。

**毛玻璃需要 `private_mac_apis` 构建标签。** 窗口背后是 macOS 原生毛玻璃，但要透出来，WebView 本身必须透明；Wails v3 只有带这个标签时才会把 WebView 设成透明，否则 WebView 画白底，把毛玻璃整个挡住。`Taskfile.yml` 已默认加上（`EXTRA_TAGS`），`wails3 dev` / `build` / `package` 都会带。代价是用了私有 API，不能上架 Mac App Store。直接 `go build ./cmd/desktop` 不带这个标签，也能运行，只是没有毛玻璃。

### 发布

**自动发版。** main 上每合进 3 个标题是 `feat` / `fix` / `perf` 的 PR,`.github/workflows/auto-release.yml` 就在最高的正式版上把最后一位加 1(如 v0.0.4 → v0.0.5),先跑 `go test ./...`,通过后打 tag 并发布。`ci`、`docs`、`test`、`refactor` 等 PR 和不经 PR 直接推到 main 的提交不计数(规则见 `.github/scripts/next-version.sh`)。要改第一、二位时手动推 tag(如 v0.1.0),之后从它接着数。每次运行的摘要里写着基准版本、计数和发没发。

- **数据库结构变了照常发。** 新版打开旧版建的数据库时会先备份再升级(见 [ADR 0003](../../docs/adr/0003-database-upgrades-step-by-step.md)),升级对不对由发版前的 `go test` 检查。只有基准版本里已发布的升级文件被改动或删掉时(`.github/scripts/check-migrations.sh`),自动发版只在摘要里提示、不打 tag,改回去后下一次推送重新判断。
- **tag 打了、版本没发出去时。** 计数以 tag 为准，不看 Release 有没有发成功，所以要手动补：问题不在代码(如 runner 临时出错)时，在 tag 上重跑 Release(`gh workflow run release.yml --ref v<版本>`);问题在代码时，删掉远端的这个 tag(`git push origin :refs/tags/v<版本>`),修好合进 main 后，下一次推送会重新判断，在新的提交上发同一个版本号。

**手动发版。** 推送 `v<X.Y.Z>` 形式的 tag(如 `git tag v0.1.0 && git push origin v0.1.0`)后，`.github/workflows/release.yml` 在 GitHub Actions 上构建各平台的安装包，再发布到同名的 GitHub Release:macOS 通用 `.dmg`(Apple 芯片 + Intel)与给 app 里的更新用的 `.zip`、Windows amd64 的 NSIS 安装程序、Linux amd64 / arm64 的 `.AppImage`、`.deb`、`.rpm`、`.pkg.tar.zst`,另附 `SHA256SUMS.txt`,发布后再传一份 `release.json`(app 检查新版本时读的发布信息)。tag 带 `-` 后缀(如 `v0.2.0-beta.1`)时发布成预发布版本。

- 版本号以 tag 为准：构建前由 `.github/scripts/set-version.sh` 写进 `build/config.yml`(关于页显示的版本)、`Info.plist`、Windows 版本资源、NSIS 与 nfpm 配置，仓库里这几处的版本号不用手改。macOS 与 Windows 的版本字段只认数字，预发布后缀只留在 `config.yml` 与 Linux 包里。
- **`release.json` 是 app 检查新版本依赖的约定**:app 从 `releases/latest/download/release.json` 读最新正式版附带的这份文件(`release.go` 的 `releaseManifest`),字段是 GitHub releases 接口返回内容里的 `tag_name`、`body`、`html_url`、`published_at` 与 `assets` 的 `name`、`browser_download_url`、`size`,由 workflow 的 Release manifest 一步生成。最新正式版上缺了它、改了名或少了字段，这之后装出去的 app 都查不到新版本(只报连不上 GitHub);这一步失败时，在 tag 上重跑 Release 不行(版本已存在),按 workflow 里的那两条命令手动生成并 `gh release upload v<版本> release.json` 补传。
- **安装包的文件名是 app 里的更新依赖的约定**:`Mechbox-<版本>-macos-universal.zip`、`-windows-<架构>-setup.exe`、`-linux-<架构>.AppImage` 与 `SHA256SUMS.txt`,app 按这几个后缀找本平台的安装包和校验值(`release_<平台>.go` 的 `releaseTarget`)。改名、去掉其中一个，已经发出去的版本就找不到安装包，只能打开下载页;发布正文里 GitHub 生成的 `## What's Changed` 是 app 里显示的更新说明的开头。
- 各平台的打包与安装包命名在 `Taskfile.yml` 的 `release` 任务里，workflow 在每个平台上只调它。在本机调试打包就在 `cmd/desktop` 下运行 `wails3 task release`(可加 `VERSION=<版本>`),打出本机系统、本机架构的安装包放进 `dist/`;它不写版本号，要和正式发布一致先跑 `set-version.sh`。
- 在 Actions 页面选一个分支手动运行这个 workflow 只构建、不发布，安装包留在那次运行的 Artifacts 里，文件名里的版本是 `dev-<提交>`;选 tag 运行则和推 tag 一样发布。
- Windows 构建要开 cgo(`CGO_ENABLED=1`,技能库用的 SQLite 驱动需要),Windows 任务默认不开。
- macOS 只做 ad-hoc 签名、没有公证，Windows 安装程序也没有代码签名;用户第一次打开时会被系统拦一下，Release 说明里写了怎么放行。

## 运行时行为

- **技能库位置**：`<用户配置目录>/mechbox/library.db`，macOS 上是 `~/Library/Application Support/mechbox/library.db`;设了 `MECHBOX_LIBRARY` 时是它(本地调试用，见上文“开发”)。首次启动时创建目录，由 Library 初始化空库。它只依赖 `HOME`，所以从 Finder / Dock 启动也能找到。
- **设置都在数据库里**(ADR 0011):设置页里的一切都由技能库存进数据库的 `config` 表，只认这里，不读环境变量，也不用系统钥匙串或设置文件。
  - 应用设置：检查技能更新、通用(含外观与浅色、深色两份毛玻璃浓度)与 Agent 的显示勾选，以及这台机器是否打开过 app(第一次打开时带用户入库已有的技能)。经 `Library.AppSettings` / `SetAppSettings` 整组读写，数据库里没有的项取默认值，加设置项就是给 `Settings` 加字段。随推送、拉回走，拉回后换成拉回的那份库里的，立即生效(界面语言、外观随之切换);这台机器已经打开过 app 的记录保留。
  - GitHub 令牌(`Library.GitHubToken` / `SetGitHubToken`):随推送、拉回走，拉回后换成拉回的那个。没填时匿名访问，受限时再用 `gh` 的登录。
  - AI 设置(`Library.AISettings` / `SetAISettings`):接口类型(OpenAI 兼容或 Anthropic)、服务地址、API Key、模型，以及请求头(一行一个「名字: 值」)与请求体(合并进每个请求的 JSON 对象，用来设置思考深度这类参数),随推送、拉回走;翻译描述和关系图里判断单个词的技能名都用它。「测试连接」(`Library.TestAISettings`)用表单上还没保存的那一组发一条很短的消息。
  - 自动翻译技能描述：AI 分区里的开关，是应用设置，默认打开。开着且填了模型时，主界面把快照里还没有界面语言译文的描述每 8 个一批交给 `Library.TranslateDescriptions`,翻完一批重读一次;中文界面下技能库跳过已经是中文的描述，其他语言交给模型判断。只因某一条描述没翻译成的(服务拒绝了这一条、回答被截断)提示是哪几个技能，这次不再交，其余照常翻译;连不上、超时、限流时提示一次，过一分钟自己再试;Key 被拒、模型不存在这类失败提示后停下，改了 AI 设置、在设置里把开关关掉再打开，或退出后重开时再试。
  - 同步设置(`Library.SyncSettings` / `SetSyncSettings`):只属于这台机器，推送出去的库里不带，拉回时保留本机的。缺存储桶或密钥时同步报未配置。设了自动推送的间隔时，`AppService` 每分钟看一次是否到了(按 `Library.SyncStatus` 的上次推送时间),到了就推送;失败后一小时内不重试，改了同步设置就不等。上一次推送(自动或手动)失败、或删不掉超出份数的旧备份时，`AppService.PushProblem` 给出原因，左栏写「推送失败」，同步弹窗与设置页写出原因。
  - 密钥以明文存在数据库里：数据库所在目录建成 0700,打开时把数据库文件(连同 -wal、-shm)改成 0600;数据库开着 `secure_delete`,清空或换掉的值在文件里清零。拉回后 Go 端发 `settings-reloaded` 事件，开着的设置页随之重读。
- **自动检查更新**：默认打开、每天。Go 端每分钟看一次是否到了间隔（以技能库里记下的检查时间为准，从未检查过的技能从入库时算起，手动检查也算）；“只在打开时”是启动应用、从菜单栏或 Dock 重新打开窗口时各检查一次。只检查非本地目录来源的集合，不发系统通知；检查完更新 Dock 角标，并发 `updates-checked` 事件让前端重读。自动检查和在 skills.sh 上给未纳管技能找来源都要读来源，两件事轮流进行、不同时跑(手动检查更新不用等):启动时正在自动检查的话，未纳管技能行里的"来自 …"要等检查做完才出现;反过来，正在找来源时到了检查时间，自动检查推迟到找完再做。各自做完后立即把空闲内存还给系统。
- **Dock 角标**：计入角标的技能数，按技能库给出的 `UpdateCheck.Pending`(有新版本且没跳过、来源里已删除且没选继续保留、推测出改名;本地目录来源、跳过的改动、新技能不计入),和左栏"更新"的计数一致；前端每次重读快照后经 `AppService.RefreshBadge` 重算。只在 macOS 上显示。
- **卸载 Mechbox**:设置页最后一个分区。弹窗先现查各处安装的状态，写明会删什么(技能库，连同设置页里的设置、GitHub 令牌、AI 设置与同步设置;应用本身);配置了同步时提醒可以先推送(「先去同步…」打开同步弹窗),没配置时写明无法恢复。已安装的技能文件夹按全局、各项目分开计数，三选一：保留(默认，Agent 照常使用)、移到废纸篓但保留被改过的几处、全部移到废纸篓;被改过的逐处列出。确认后移文件夹(已经不在的、在不在这台机器上的项目里的跳过),中途失败时数据库不动，重试时跳过已经移走的。然后退出，技能库关上以后再删数据库(目录空了连目录一起删)、`~/Library` 下 WebKit、Caches、HTTPStorages、Saved Application State、Preferences 里这个应用的数据，最后把 `.app` 移到废纸篓，移不动时在 Finder 中选中它。S3 上的备份不动。不在 `.app` 里运行(如 `go build` 出来的)时不动可执行文件;Windows / Linux 上:
  - 退出后只删数据库，应用本身和 WebView 的数据不动，弹窗里写明应用要用系统的方式卸载。
  - Windows 上文件夹移到回收站，弹窗里说「回收站 / Recycle Bin」;WSL 发行版里的文件夹(`\\wsl.localhost\...`)进不了 Windows 回收站，经 `wsl.exe` 按 freedesktop 规范移进那个发行版的 `~/.local/share/Trash`。
  - Linux 上文件夹按 freedesktop 规范移进 `$XDG_DATA_HOME/Trash`(默认 `~/.local/share/Trash`);和家目录不在同一个文件系统上时，放进那个卷顶层的 `.Trash/$uid` 或 `.Trash-$uid`。弹窗里中文说「回收站」,英文说 Trash。
  - 进不了回收站时报错，那一处留在原处、不直接删除;弹窗提示可以改选保留后重试。
  - server 模式下只删数据库，文件夹直接删除。
- **WSL 发行版里的 Agent**:Windows 上装了 WSL 时，设置页「通用」里选各 Agent 的全局目录在 Windows 本机(默认)还是某个 WSL 发行版，由技能库存进数据库(`Library.SetWSLDistro`,只属于这台机器，推送不带、拉回保留),启动时取出(`Library.WSLDistro`)再交给技能库。选了发行版后，全局目录换成发行版主目录下的(`\\wsl.localhost\<发行版>\home\<用户>\...`),之前装在 Windows 本机全局目录里的技能留在原处、不再管;数据库、令牌、同步设置与自动检查都只有一份，不随它变。改选时打不开发行版就不保存，报错说明原因;启动时打不开，技能库先用 Windows 本机的全局目录，主界面弹窗说明原因，可以再试或改回 Windows 本机(`AppService.WSLDistroError`、`RetryWSLDistro`);关掉弹窗时提示现在用的是 Windows 本机的全局目录，设置页这一项下面也一直写明，并可以再试一次。WSL 没有响应时，启动最多等 30 秒就按打不开处理。卸载 Mechbox 时要移走的文件夹里有发行版里的，弹窗写明它们进那个发行版的回收站、怎么找回。不论选的是哪里，登记在发行版里的项目、发行版里的本地目录来源也都按发行版里的规则读写(符号链接、可执行权限经 `wsl.exe` 在发行版里处理，见技能库的包说明)。
  - **界面上怎么区分**：在 WSL 里的地方带 `WSL · <发行版>` 标记(和设置里下拉选项的写法一样),没有标记的就在 Windows 本机。标记出现在右栏「全局」标题(全局目录选了发行版时)、右栏项目行与设置页的项目列表(项目在发行版里时)、作用域页的 Agent 目录、项目页的项目目录，以及本地目录来源的名字(左栏集合、技能库页的分节标题、技能详情、入库预览)。发行版里的路径写成 Linux 路径：在全局目录所选发行版的主目录下的写成 `~/...`,其他写成 `/` 开头的绝对路径，悬停给出完整的 `\\wsl.localhost\...`;Windows 本机的路径照旧完整显示。不在 Windows 上时(如拉回的库里带着发行版里的来源)照原样显示。
  - **路径输入**:入库框、登记项目与改项目位置、自定义 Agent 的全局目录里，`~/...` 是全局目录所在的主目录(选了发行版时是发行版的主目录)。装了 WSL 发行版时，`/` 开头的路径在全局目录选了发行版时当作那个发行版里的路径，选 Windows 本机时拦下(不猜是哪个发行版，提示用「选择…」或写成 `\\wsl.localhost\<发行版>\...`;自定义 Agent 的全局目录则提示先在设置里把全局目录换到发行版);没装 WSL 时照原样交给技能库。这几个输入框下面写出输入会被理解成哪里(「WSL · Ubuntu 里的 /home/...」或「Windows 本机的 C:\...」),只在装了 WSL 发行版的 Windows 上有。改项目位置时预填的原路径，用户改动之前不报错。
- **界面语言**：设置页「通用」里选跟随系统(默认)、简体中文或 English,存在数据库的应用设置里(跟随系统时不写)。跟随系统时由 Go 端判断系统语言(`AppService.Language`):macOS 读系统设置里排第一的首选语言(`[NSLocale preferredLanguages]`,不用 WebView 的 `navigator.language`,它跟随 app bundle 声明的语言),Windows 读系统设置里排第一的显示语言(`GetUserPreferredUILanguages`,Windows 一般不设 `LANG` 等环境变量),其他平台与 server 模式读 `LC_ALL` / `LC_MESSAGES` / `LANG`;首选中文(含繁体)时用中文，其余用英文。前端等 Go 端给出语言再渲染，改了设置整个界面立即切换，菜单栏图标的菜单与 macOS 顶部菜单栏同时换文字。系统控件(目录选择框的按钮、输入框的右键菜单等)跟随系统语言，不跟随这里的选择;`Info.plist` 声明了 en 与 zh-Hans 两种本地化，系统控件才会按系统语言显示中文。
- **外观**：设置页「通用」里选跟随系统(默认)、浅色或深色，存在数据库的应用设置里(跟随系统时不写)。前端(`lib/theme.ts`)按设置与 `prefers-color-scheme` 在根元素上写 `data-theme`,渲染前就写好，系统切换深浅色时立即跟着变;毛玻璃浓度浅色、深色各存一个值(`glass_tint` / `glass_tint_dark`),换外观时平滑过渡到那个外观的值。窗口背后的系统材质由 Go 端跟着换(`AppService.applyAppearance`):macOS 设整个 app 的外观(跟随系统时交给系统),Windows 设窗口的深浅色(Mica 跟着变)与没有 Mica 时的不透明底，窗口显示出来与系统切换深浅色时再设一次。
- **关闭窗口**：“关闭窗口后留在菜单栏”打开（默认）时，关闭窗口只是隐藏，Dock 图标和角标仍在，菜单栏出现一个入口（打开 / 退出）；点它或 Dock 图标重新打开窗口，入口随之消失。关掉时关闭窗口就退出。
- **新版本**(`release.go`):正式版启动时与之后每天读一次 GitHub Releases 上最新的正式版(不含预发布)附带的 `release.json`,没读成时隔一小时再试;比当前版本新时左栏出现新版本那一行。设置页「关于」里与 macOS 顶部菜单「Mechbox → 检查新版本…」可以随时检查，菜单里检查时有新版本直接打开新版本对话框，否则用 toast 说明结果。`release.json` 由发版工作流在发布后从 GitHub 读回这个版本再作为附件传上去;app 从 `releases/latest/download/release.json` 下载它，和下载安装包一样不经 GitHub API,不占 API 每小时 60 次的匿名额度(拉取技能、检查技能更新都先用这份额度),也不需要令牌。检查结果只在内存里，不写数据库;一次检查最多等 30 秒。更新说明从 GitHub 生成的 `## What's Changed` 开始显示，略过前面手动安装的说明。「更新」由 Wails 的 updater 下载本平台的安装包、按版本附带的 `SHA256SUMS.txt` 校验，然后按平台装上：
  - macOS 下载 `-macos-universal.zip`,Wails 另起一个自己做 helper,等 app 退出后先备份再替换 `.app`,用 `open -n` 启动新版，失败时还原备份。`.app` 所在文件夹不能写入时(没有权限，或直接从 dmg、被系统隔离运行的位置打开)只给下载页。
  - Windows 下载 `-setup.exe`,起一个隐藏的 PowerShell:等 app 退出后用管理员权限静默运行安装程序(`/S /D=<当前安装目录>`,弹一次 UAC),不管装没装成都再启动安装目录里的 `mechbox.exe`。
  - Linux 上从 AppImage 运行时(有 `APPIMAGE`)下载 `-linux-<架构>.AppImage` 换掉原文件，等 app 退出后启动它;deb、rpm、pkg.tar.zst 装的只给下载页。
  - 下载失败、校验不通过时对话框里写出原因，当前版本不变，可以再点。下载途中可以停止(关掉对话框也一样),下载完进入校验、装上后对话框锁住;有写操作进行中时「更新」不能点。
  - 新版本在 app 退出后才装上，所以点「更新」时在数据库所在的目录里记下 `update-pending.json`(版本与安装记录的位置:macOS 是 Wails helper 的日志，Windows 是安装脚本写的 `update.log`,里面是安装程序的退出码)。下次启动时版本还不是它，就提示「上次没有装上」和记录的最后一行，打开新版本对话框时也写着。
  - 开发版与 server 模式见上文"开发"。
- **单实例**：同一时间只运行一个实例。再次启动时，新进程直接退出，把已有窗口带到前台（最小化了也会恢复）。单实例检查早于打开技能库，第二个进程不会碰库文件。实例按数据库区分：用 `MECHBOX_LIBRARY` 打开别的数据库的开发版窗口，可以和装好的 app、和别的数据库的窗口同时开着（见 [测试改动](../../docs/testing.md) 的「几个工作区同时开窗口」）；指向真实技能库的仍和装好的 app 共用一个实例。同一个数据库换一种路径写法(经过符号链接、在不区分大小写的卷上换了大小写)、建库前后都算同一个实例。
- **启动失败**：打不开数据库等启动错误，先弹系统提示框写明原因与数据库位置，用户关掉后才退出;原因同时打到 stderr。

## 测试

改完代码后跑哪些检查、测试放在哪里、怎样跑端到端验证、怎样用开发数据在 app 里验证，都见 [测试改动](../../docs/testing.md)。

`frontend/dist/` 里提交了一个占位文件 `.gitkeep`（源文件是 `frontend/public/.gitkeep`，每次 Vite 构建都会复制过去），所以没构建前端时 `go build/vet/test ./...` 也能通过，纯 Go 的开发不需要 Node 工具链。

### 界面文案

界面上看得到的文字(JSX 文本、`title` / `placeholder` / `aria-label` 等属性、toast、弹窗、错误文案)都写进 `frontend/src/lib/i18n/` 的两份文案文件，新增文案时中英一起写：`zh.tsx` 是唯一来源，按界面区域分组;`en.tsx` 照它的结构翻译，`satisfies Messages` 让漏翻、参数不对的条目在 `tsc` 里报出。

- 组件里用 `useT()` 取当前语言的文案;组件外的函数(`model.ts`、`features/` 里的写操作流程等)用 `messages()`。
- 带变量的句子写成函数，整句交给文案文件：不要把半句话当参数传，也不要在组件里拼接两句文案(英文语序不同，句子之间还要空格)。带格式的句子(如加粗的名字)让函数返回 ReactNode。
- 英文的单复数、列表(`Intl.ListFormat`)在 `en.tsx` 里处理;中文列表照旧用顿号。日期统一经 `formatDate`,数字的 `toLocaleString` 显式传语言。
- 英文用词：术语表(`CONTEXT.md`)里有的概念用术语表的英文名。
- 按平台换说法的文案(如卸载时的废纸篓 / 回收站)在文案函数里调 `lib/platform.ts` 的 `platform()`,组件不传平台。
- Go 这边的菜单文字在 `menu.go` 的 `nativeLabels`,同样中英两份;启动失败提示框的文字在 `startup_error.go`,也是中英两份，按系统语言选(这时读不到数据库里的语言设置)。

### 给前端加一个技能库调用

1. 在 `library_methods.go` 里加一个方法，签名沿用技能库的：`ctx` 在前，返回 `(T, error)`。转发时经 `settle` 包一层：`return settle(s.lib.X(ctx))(ctx)`。前端取消调用后 Go 端若仍返回错误，Wails 会把它报成未处理的 rejection，`settle` 负责把这种错误吞掉。
2. 重新生成绑定。`wails3 dev` / `build` 会自动生成；也可以手动运行 `wails3 generate bindings -clean=true -ts -i`。生成的文件要提交：PR 与 main 上的 Check(`.github/workflows/check.yml`)会重新生成一遍，和提交的不一致时检查失败。
3. 前端从 `@bindings/cmd/desktop` 导入 `LibraryService`，类型从 `@bindings/internal/library` 导入。读库里现有状态的只读调用写成 `lib/library.ts` 里的查询(TanStack Query 的 `queryOptions`,经 `wails` 把查询的 `signal` 接到可取消的调用上),组件里用 `useQuery` 取;快照用 `useSnapshot()`,不经 props 传。内容只由 key 决定、或来自技能库以外的查询标 `meta: stable`,写操作后不重读。生成计划、入库预览这类流程里的一步会在 Go 端留下状态，不做成查询，在弹窗或流程里直接调用，关掉时 `cancel()`。写操作放进 `features/` 里对应流程的文件，经 `ui.run` 执行——它负责忙碌状态、按错误码提示，并在完成后让查询缓存失效重读(`reloadLibrary`)。

错误：Go 端所有错误都经 `library.ErrorOf` 规范成技能库错误，再编码给前端。前端从 `err.cause` 拿到 `{code, message, details}`，用 `lib/library.ts` 的 `toLibraryError` 读取。

### 界面样式

主界面的外观以 UI 原型（分支 `worktree-prototype-wails-ui` 的 `cmd/prototype-wails`，变体 A）为准，用 shadcn/ui 组件 + Tailwind 实现(ADR 0008)。

- 控件用 `components/ui/` 里的组件(Button、Badge、Switch、Slider、Dialog、Sheet、Popover、Tooltip、ContextMenu、Input、NativeSelect、Segmented、Card、Notice、ListBox / ListRow、Field / Hint),不在组件外另写一套同类控件。
- 悬停说明一般写 `title`;原生 `title` 在可拖动的元素(技能行、左栏的集合与组)上不出现，这些地方要悬停看截断的全文时用 `components/app/parts.tsx` 的 `Truncated`(放不下才弹 Tooltip)。shadcn 的组件代码复制进来后按本应用改过，改动写在各文件开头。
- 颜色、圆角、阴影用 `index.css` 里的主题(`text-foreground`、`border-border`、`rounded-tile`、`bg-glass-card` 等),不写一次性的色值：写死的白底、黑色透明度和色板颜色在深色下会露出来。主题里的颜色在 `@theme` 里是浅色的值，深色的值在 `:root[data-theme="dark"]` 里整组换掉;加颜色时两处一起加，深色按层级排(越靠前的层越亮，凹进去的比所在的面暗)。几个容易用错的：写成字的主题蓝用 `text-primary-ink`(深色下更亮),写白字的实心蓝底用 `bg-primary-solid`(深色下更深);叠在内容上的深浅用 `bg-fill` / `bg-fill-subtle` 等(浅色是黑、深色是白),半透明的白用 `bg-wash/55` 这样取透明度;阴影的颜色经 `--shade-*` 给出，Tailwind 把阴影值直接写进工具类，只换 `--shadow-*` 不起作用。
- 铺在底板上的表面透出窗口背后的系统材质(macOS 的毛玻璃,Windows 11 22H2 起的 Mica;更早的 Windows 是 `appearance_windows.go` 里的不透明底，浅色、深色各一份),只用半透明白色(深色下是很淡的白):`glass-tile`(三栏底板)、`glass-card`(摘要条与弹层里的卡片)。
- 浮在内容上的表面(弹窗、抽屉、弹层、提示、右键菜单、勾选后的操作栏、吸顶的节标题、toast)用 `index.css` 的 `glass` 工具类(铺满窗口的弹窗除外，如版本比较：它是用来读内容的，用不透明的浅灰底 `bg-surface`,里面的几块用白底):只换底色、滤镜、边缘与字色四样，投影经 `--glass-drop` 沿用各自原来的档位;背后内容少、上面字也少的(操作栏、toast、提示)另加 `glass-clear`,模糊轻、白色淡;表面上的 `text-foreground` 等换成墨色，状态色不变。浓度乘以设置里的毛玻璃浓度(`lib/glass.ts` 的 `applyGlassTint`)。边缘是扁平的：只有一圈均匀的细线，不加斜面亮线、内侧柔光、高光或折射这类立体效果。窗口背后透明(透出 Mica),Chromium 把模糊后的背景叠在原内容上，结果半透明时没模糊的字会从玻璃底下透出来，所以启动时 `installGlass` 在 Chromium 上给所有玻璃接一个把背景变不透明的滤镜(`--glass-solid`)。玻璃的祖先不要加 `backdrop-filter`:在 Chromium 里它会截断背景，里面的玻璃模糊不到底下的内容(中间底板因此不加)。毛玻璃上高亮的一行用 `bg-glass-row-hover` / `bg-glass-row-selected`,不用灰色。系统要求减少透明度或开了强制颜色时，玻璃换成同色的不透明底，设置里的浓度滑块禁用;macOS 的 WKWebView 不认 `prefers-reduced-transparency`,由 `AppService.ReduceTransparency` 读系统设置，启动和窗口重新获得焦点时在根元素上标 `data-reduce-transparency`。加 shadcn 组件时先把默认的不透明背景和深色遮罩换成这些。
- 顶栏(`components/app/titlebar.tsx`)就是窗口的标题栏：整条是拖动区，macOS 上左端给红绿灯留位置;Windows 上窗口没有系统标题栏，最右端画最小化、最大化、关闭三个按钮(照 Windows 11 的样子，字形用系统的 Segoe Fluent Icons),双击空白处最大化或还原，弹窗开着时也能用。Windows 上调整大小只能从窗口内侧边缘的几像素开始(Wails 前端运行时处理),窗口外侧没有系统的调整区。
- 禁用的白底控件只把文字调淡，不整体降透明度，否则白色按钮会融进毛玻璃背景;蓝色主按钮禁用时降透明度。
- 按钮的 `loading` 让文字留着占位、上面盖一个转圈，按钮宽度不变;弹窗贴着窗口上部出现，内容变高时只往下长。
- 详情抽屉是非模态的 Radix Dialog,在主体区域里原地渲染、没有遮罩：抽屉开着时其他地方照常可用，点别的技能行切换、再点当前那一行关闭，Esc 或关闭按钮也能关;在列表里点空白处(技能行、节标题、作用域页与项目页顶部的摘要条和各种控件以外)也关上，但抽屉里正在写备注、开着下拉框或菜单时这一下只让输入框失焦、收起弹层，选中了文字时也不关。列表里新加能点的东西要用按钮、链接或带 role 的元素(或加进 `skill-list.tsx` 的 `notBlank`),否则点它也会关上详情。关上时抽屉右移并淡出，播完才卸载。弹窗(`Modal`)是模态的，叠了几层时 Esc 只关最上面一层。
- `index.css` 只放工具类管不到的：页面基础样式、窗口底色(`window-backdrop`)、毛玻璃材质(`@property` 登记的 token 与 `glass`、`glass-clear` 工具类，以及要压过 `glass` 的状态，集中写在层外)、渲染出来的 Markdown(`.md`)、拖放中的高亮(按 `data-dragging`、`data-drop-hover` 等属性),以及状态圈(`.status-mark`)与 toast(`.swipe-toast`)按状态切换的动画。
- e2e 按两类钩子找元素：通用控件用 `data-slot`(`dialog-content`、`badge`、`list-row` 等)或角色(`role="switch"`、`aria-pressed`);应用自己的结构用类名(`skill-row`、`section-head`、`nav-item`、`set-row` 等)。这些类名不挂样式，改结构时保留。
