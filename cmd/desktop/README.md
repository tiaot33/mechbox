# 桌面端

Mechbox 的桌面端：Wails v3 应用，Go 进程直接持有技能库（Library），React 前端经 Wails 绑定调用它（ADR 0008）。macOS 一等支持，Windows / Linux 只保证能编译。

以下命令都在 `cmd/desktop/` 目录下执行。

## 功能

桌面端覆盖技能库(Library)的全部功能，界面按 UI 原型变体 A 组织：

| 界面位置 | 功能 |
| --- | --- |
| 左栏"入库技能" | 一个输入框:本地路径(可点"选择…",`~` 展开为主目录)、GitHub(`owner/repo`、`owner/repo@技能名`、github.com 链接)、GitLab 等 Git 仓库地址(含 SSH)、SKILL.md / zip / tar 下载链接或站点链接，由技能库识别来源;输入是 Git 仓库时，停下输入约半秒后从技能库取分支和 tag,在扫描前从下拉里选(分组列出、可筛选，默认选中默认分支，输入里带了分支时选中它;改选别的分支时只在发给技能库的请求里换掉输入里的分支(去掉结尾的 `#<分支>`,或换掉 tree 链接里的分支、保留目录),输入框里的文字不变;取不到时显示原因，仍可入库预览),只看某个目录就粘贴 tree 链接;识别失败时在对话框里显示原因。入库预览结果页先写识别结果(来源类型、展示名称、分支),在候选里勾选入库;诊断列出未成为候选的路径，GitHub 仓库可按需查看 skills.sh 审计，没有 GitHub 令牌时提醒容易被限流 |
| 左栏"技能市场" | 搜索 skills.sh,选中后做入库预览并入库 |
| 左栏 | 页面：所有技能、更新(要处理的更新数，和 Dock 角标同一套规则);检查更新(按来源，本地目录来源不检查);按来源的集合(每个来源一行，按来源名排，只有一个技能的也列出)与组(新建 / 重命名 / 删除，悬停组行出现按钮)不是筛选，点了回到所有技能页、按它分节并滚到那一节;集合行、组行都能拖到右栏作用域 |
| 所有技能页 | 永远列出库里全部技能，按集合或按组分节(页顶切换)。按集合时每个来源一节，按来源名排，没有来源的技能合进最后的"没有来源";按组时每个组一节，一个技能在几个组里就出现几次，不在任何组里的合进"没有归组"。一个技能一行：名字与标记(有新版本、来源里已删除、同名、所属的组)、一行描述、装在哪(显示的 Agent 全局都装了只写"全局",否则写出是哪几个 Agent;一个项目写项目名，多个写个数;要重新安装时标黄)、最近变化(更新时间，没更新过写入库时间;七天内的颜色深一些)。节里的技能按来源、名字排，同名的最近变化的在前;装在至少一个地方的在前，没装的折成一行，点开再列出(搜索时、或一节里一个都没装时直接全部列出)。节标题可以收起，吸顶时贴着底板上沿;最后一节至少一屏高，左栏点了靠后的集合或组也能滚到顶上 |
| 搜索(⌘K) | 只在当前页里找名字与描述，页顶写出搜的是什么、几个结果，可以清除 |
| 更新列表 | 每个有要处理的更新的集合一行：来源版本从哪到哪、哪些技能有变化、可能改名或来源里已删除，以及风险提示(新增或改动的脚本、新增的可执行文件);"查看"打开更新计划，"更新"按默认勾选直接执行，多个时可"全部更新";要处理的改动都会换掉你的修改时，这一行(和技能行)写明，"更新…"只打开更新计划;来源版本未知的技能如实写出 |
| 更新计划 | 先标风险，再给 GitHub 的提交说明，点技能或风险看文件差异(SKILL.md 按文档、脚本按代码);技能有变化的默认全勾(从技能发起时只勾这一个、其余折叠，并提示集合会不在同一个来源版本上;用目录里的修改更新过的技能有变化时标明"更新会换掉你的修改"、默认不勾),可以跳过单个技能的这次改动或整个来源版本;改名推测回答"是 / 不是",来源里已删除的选"移除 / 继续保留";顺带提来源里的新技能("去入库" / "不感兴趣");下面勾选装出去的地方(默认全勾;改过的地方、文件夹不在了的地方默认不勾并写明原因，勾上才覆盖、才装回去;项目不在这台机器上的不能勾)。一次确认先换库、再逐处重新安装，计划生成后来源变了时提示重新生成;完成提示带"回滚",没换上的地方列出原因、可以重试 |
| 集合的节标题 | 在用几个、共几个，集合里的技能在哪个来源版本上、有几个有变化、更新、历史(每次更新、跳过、回滚各一条;更新可以回滚，跳过的可以找回来再更新)、来源里的新技能，以及"看来源里的其他技能"(对已有集合再做一次入库预览) |
| 组的节标题 | 组安装于哪些作用域(可以卸载)、重命名、删除组;接受拖来的技能(加入该组) |
| 技能行 → 详情抽屉 | 描述(有界面语言的译文时显示译文，可以切到原文;「翻译」每次都用 AI 重新翻译，存进数据库)、备注(只存在数据库里，列表里鼠标停在技能名字上显示)、元数据(检查更新的结论、和同一来源其他技能的关系)、来源里已删除时的"移除 / 继续保留"(继续保留的只留淡色标记)、可能改名的说明、加入 / 移出组、各作用域的安装与状态(直接安装开关、单条重新安装、安装到…;被手动改过的地方可以"用这里的修改更新":看差异，勾选其他地方一起换成这份修改，用户改过的地方默认不勾，完成提示带"回滚")、文件浏览(SKILL.md 渲染)、版本历史(来源版本、与当前比较、查看旧版文件)、更新(打开所在集合的更新计划，只勾这一个)或重新读取(本地目录来源：一个操作读出新版本并换到装过的地方，改过的、文件夹不在了的地方不动;目录没变时把还没换上的地方补上)、更新历史(哪几次更新改过它，可以回滚)、只有一个技能的来源上"看来源里的其他技能"(点过"不感兴趣"的新技能也能找回来)、全部重新安装、移除技能 |
| 右栏作用域 | 全局与已登记项目下的各 Agent(左右两栏与技能详情抽屉都可以拖动边缘调宽，双击恢复默认，宽度记在这台机器上);登记 / 改位置 / 注销项目，项目目录不在这台机器上时带标记;点一行打开这个作用域的页面，再点一次回到所有技能 |
| 作用域页 | 回答 Agent 在这里看得到什么。顶部写出一共看得到几个技能、Agent 目录与健康状态、全部重新安装、各组的组安装开关;下面库里的技能和所有技能页一样按集合或按组分节(同一个切换),行带直接安装开关;节标题写装在这里几个，节里装在这里的在前，没装在这里的折成一行(只有一个时直接列出),点开再列出;之后是这个作用域里的未纳管技能一节，以及来自全局的一节(只在项目作用域里有：同一个 Agent 全局装的技能与未纳管技能，Agent 在项目里也看得到，默认收起，这里不能开关，也不再出现在前面的节里)。未纳管技能(不是库装的技能文件夹，标"未纳管"，提交在项目仓库里的标"在项目仓库里"，符号链接写出指向哪里),可以"在 Finder 中显示"或"入库"(确认时写清：交给 app 管以后再用命令行工具更新，只能报为被手动改过;项目仓库里的之后在 app 里更新会改动仓库里的文件),不能删除。npx skills 的来源记录里记了来源的，行里写"来自 …"，入库确认里预填成来源链接，写明以后跟着它检查更新;记录认不出来源的，列出之后在后台按名字去 skills.sh 搜，内容和搜到的同名技能大部分相同时同样写"来自 …"、预填(这次打开 app 里找过的不再找，确认框开着时找到的、用户还没改链接就补上);用户可以改链接或清空，读不成来源(连不上、来源里没有、认不出、集合里同名但内容不一样)时留在框里说明，可以重试、改链接或清空。带来源入库的进这个来源的集合，和来源里的不一样、又说不清是不是改过的，版本历史里写"入库时和来源里的不一样，可能有你的修改"，更新计划里同样提示会换掉修改、默认不勾。入库时磁盘上什么都不改(符号链接照样是符号链接);不带来源时和库里某个版本一致只补记这一处安装，否则成为没有来源的技能：技能行与详情写"没有来源"，不检查更新、不计入角标，在装出去的地方改了以后用那里的修改更新;同一个 Agent 的全局和某个项目里有同名技能时(不论是不是库装的),两处的行都标"同名"，并写出在这个 Agent 里会怎样(Claude Code 里全局的生效，Codex 里两份都会出现，自定义 Agent 只说同名) |
| 第一次打开、登记项目之后 | 在这台机器上第一次打开 app 时(记在数据库的应用设置里，换到新机器也一样;拉回一份没有这条记录的库也不会再当作第一次),直接打开各 Agent 全局目录里不是库装的技能的确认;每登记一个项目，打开这个项目里的。先写磁盘上什么都不改、Agent 用的和现在一样，再写唯一的代价(之后还用命令行工具更新，只能报为被手动改过);第一次打开时说明项目里的登记项目时再接。按认出的来源(含在 skills.sh 上找到的，找到后补上)分组，内容一样的几处(含符号链接)合成一条，每条确认前都可以"改来源"(改链接或清空);在项目仓库里的、项目 skills-lock.json 记的默认不勾，勾上才提醒之后在 app 里更新会改动项目仓库里的文件;同名但内容不一样的单列出来，每个只选一份，默认选最近修改的;读不出的列在"不能入库"里。按来源逐批入库，读来源时写出在等什么;一个失败不影响其余的，没入库的可以改来源链接重试或清空后不带来源入库。之后作用域摘要里淡淡写一句还有几个不是库装的(在项目仓库里的不算),"全部入库…"再打开这个作用域的确认，不计入角标 |
| 拖放 | 技能行 → 右栏作用域 = 直接安装;技能行 → 左栏的组或组的节标题 = 加入;组(左栏组行或组的节标题)→ 右栏作用域 = 组安装，之后加进组的也会装;集合(左栏集合行或集合的节标题)→ 右栏作用域 = 把集合里还没直接安装在那里的技能逐个直接安装，一次性的，之后入库的新技能不会自动装过去;被别的技能占着的跳过并说明，有不是库装的同名文件夹的合成一次询问跳过或覆盖，有没装上的列出结果 |
| 左栏"同步" | 整库推送到 S3 / 从 S3 拉回(先看同步计划：S3 上是哪台机器什么时候推送的那一份;拉回还说明里面有什么、不能拉回的原因、哪些项目不在这台机器上) |
| 左栏"设置" | 设置页(替换三栏，左边是分区目录):通用(关闭窗口后留在菜单栏、Dock 角标、语言：跟随系统 / 简体中文 / English;Windows 上装了 WSL 时还有全局目录：Windows 本机或某个 WSL 发行版)、Agent(显示勾选;添加、编辑、删除自定义 Agent,改目录时选择是否迁移)、项目(登记 / 改位置 / 注销，与右栏同一套弹窗)、检查更新(自动检查开关与间隔)、GitHub(个人访问令牌)与同步(服务地址、存储桶、对象名、区域、Access Key ID、Secret Access Key、Session Token;都存在数据库里，只认这里填的，不读环境变量)、关于(应用版本、数据库位置)、卸载 Mechbox(见下文"运行时行为") |
| 顶栏 | 当前页面的标题与个数、搜索(⌘K)、刷新(重新读取并对照磁盘巡检已安装的技能) |

Agent 的显示勾选只影响选择安装位置的地方(右栏、详情里的"安装到…"):用户没勾选过的 Agent,检测到的和自定义的显示，其余不显示;已经装了技能的 Agent 不管勾没勾，装出去的地方照常列出。右栏在每个地方直接列出装有技能的与检测到的 Agent,勾选了显示但没检测到的折进"其他 N 个 Agent"。几个 Agent 共用一个目录时，装一次这几个都算已装。项目里共用一个目录的几个 Agent(如都读 `.agents/skills`)合成一处：右栏、作用域页、技能详情的安装表与"安装到…"，以及更新计划、重新安装、结果与历史里逐处列出的地方都只列一次，叫这台机器上显示的那几个 Agent 的名字(悬停写出目录与读它的全部 Agent),点选和安装落在其中第一个的作用域上，卸载时不再另说共用;全局目录共用的照旧一个 Agent 一行，从其中一个卸载前提示还被哪些 Agent 共用。改自定义 Agent 的目录、删除自定义 Agent 时，确认框列出还有别的 Agent 在用、因而保留的文件夹。

冲突按技能库的约定处理：安装前先看安装计划，目标有不是从库里装的同名文件夹时询问是否覆盖，被另一个技能占用或作用域根目录不存在时说明原因;重新安装前先现查各处状态，被改过的几处逐处勾选是否覆盖，文件夹不在了的几处(可能是用户有意删掉的)逐处选不动、装回去还是卸载，默认不动，只点了这一处的单条重新安装直接装回去;组安装、加入组、重新安装逐条返回结果，被跳过或失败的条目列出原因;移除技能、注销项目、移出组时让用户决定磁盘上已安装文件夹的去留，并说明其中哪几处被改过。

## 准备

| 依赖 | 说明 |
| --- | --- |
| Go | 版本见根目录 `go.mod` |
| Xcode Command Line Tools | macOS 上编译 cgo 需要（`xcode-select --install`） |
| Node.js + pnpm | 前端工具链。`frontend/` 与 `e2e/` 是同一个 pnpm workspace(根在 `cmd/desktop/`,共用一份 `pnpm-lock.yaml`),在 `cmd/desktop/` 下 `pnpm install` 一次装好两边的依赖;构建时会自动执行 |
| wails3 CLI | 必须和 `go.mod` 里钉住的 Wails 版本一致：`go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.25` |

`go install` 把 `wails3` 装到 `$(go env GOBIN)`，未设置时装到 `$(go env GOPATH)/bin`；这个目录要在 `PATH` 里。装好后可用 `wails3 doctor` 检查环境。

## 开发

```sh
wails3 dev
```

它会生成绑定、启动 Vite 开发服务器（端口 9245），再编译并打开开发版应用 `bin/mechbox.dev.app`：

- 改前端（`frontend/src/`）：窗口热更新，不重启。
- 改 `cmd/desktop/` 下的 Go 代码：自动重新生成绑定、重新编译并重启应用。
- 改 `internal/library/`：不在监听范围内（监听根目录是 `cmd/desktop/`），要 Ctrl-C 后重新 `wails3 dev`。
- 按 Ctrl-C 结束。如果异常退出后再启动报 `address already in use`，是上次的 Vite 还占着端口：`lsof -ti tcp:9245 | xargs kill`。

开发版默认打开的是**真实技能库**（见下文“运行时行为”），安装操作也会写进真实的 Agent 目录。

**用测试数据库调试。** 设置(GitHub 令牌、同步设置、应用设置)都存在数据库里，不读环境变量，所以本地调试的口子只开在「打开哪个数据库」上：设了 `MECHBOX_LIBRARY=<路径>` 时桌面端打开那个文件，不打开真实技能库。它不覆盖任何一项设置，换一个数据库就是换一整套设置，不会和真实技能库的混在一起。固定的测试数据库是 `.dev/library.db`(已在 `.gitignore` 里),用它启动：

```sh
wails3 task dev:test-db
```

第一次打开时在设置页填好令牌、同步设置(同步建议填测试用的存储桶或另一个对象名，免得推送盖掉真实的那份),之后每次启动都在。想从头来就删掉 `.dev/`。也可以直接指定别的数据库：`MECHBOX_LIBRARY=/tmp/other.db wails3 dev`。「关于」里显示的数据库位置就是现在打开的那个。

这样只隔离了数据库：`~/.gitconfig`、`~/.ssh`、`gh` 的登录照常可用，调试 Git、GitHub 来源不受影响;但 Agent 目录仍按真实 `HOME` 算，安装会写进真实的 `~/.claude/skills` 等目录。要连安装也隔离，就再给一个临时 `HOME`(技能库位置和 Agent 目录都从 `HOME` 推导;Go 缓存也默认跟着 `HOME` 走，一并指回原处，免得重新下载依赖):

```sh
HOME=/tmp/skills-dev GOMODCACHE=$(go env GOMODCACHE) GOCACHE=$(go env GOCACHE) wails3 dev
```

**用开发数据调试。** 在 app 里看界面、验证改动时，用 `wails3 task dev:seed` 生成的开发数据，再用 `wails3 task dev:seeded` 启动，不用每次自己造技能。数据里有什么、怎样重置，见 [测试改动](../../docs/testing.md) 的「在 app 里验证界面」。

## 构建与打包

```sh
wails3 build     # 只编译二进制：bin/mechbox
wails3 package   # 打成 macOS 应用：bin/mechbox.app（ad-hoc 签名）
open bin/mechbox.app
```

`bin/` 不入库。

**毛玻璃需要 `private_mac_apis` 构建标签。** 窗口背后是 macOS 原生毛玻璃，但要透出来，WebView 本身必须透明；Wails v3 只有带这个标签时才会把 WebView 设成透明，否则 WebView 画白底，把毛玻璃整个挡住。`Taskfile.yml` 已默认加上（`EXTRA_TAGS`），`wails3 dev` / `build` / `package` 都会带。代价是用了私有 API，不能上架 Mac App Store。直接 `go build ./cmd/desktop` 不带这个标签，也能运行，只是没有毛玻璃。

### 发布

推送 `v<X.Y.Z>` 形式的 tag(如 `git tag v0.1.0 && git push origin v0.1.0`)后，`.github/workflows/release.yml` 在 GitHub Actions 上构建各平台的安装包，再发布到同名的 GitHub Release:macOS 通用 `.dmg`(Apple 芯片 + Intel)、Windows amd64 的 NSIS 安装程序、Linux amd64 / arm64 的 `.AppImage`、`.deb`、`.rpm`、`.pkg.tar.zst`,另附 `SHA256SUMS.txt`。tag 带 `-` 后缀(如 `v0.2.0-beta.1`)时发布成预发布版本。

- 版本号以 tag 为准：构建前由 `.github/scripts/set-version.sh` 写进 `build/config.yml`(关于页显示的版本)、`Info.plist`、Windows 版本资源、NSIS 与 nfpm 配置，仓库里这几处的版本号不用手改。macOS 与 Windows 的版本字段只认数字，预发布后缀只留在 `config.yml` 与 Linux 包里。
- 在 Actions 页面手动运行这个 workflow 只构建、不发布，安装包留在那次运行的 Artifacts 里，文件名里的版本是 `dev-<提交>`。
- Windows 构建要开 cgo(`CGO_ENABLED=1`,技能库用的 SQLite 驱动需要),Windows 任务默认不开。
- macOS 只做 ad-hoc 签名、没有公证，Windows 安装程序也没有代码签名;用户第一次打开时会被系统拦一下，Release 说明里写了怎么放行。

## 运行时行为

- **技能库位置**：`<用户配置目录>/mechbox/library.db`，macOS 上是 `~/Library/Application Support/mechbox/library.db`;设了 `MECHBOX_LIBRARY` 时是它(本地调试用，见上文“开发”)。首次启动时创建目录，由 Library 初始化空库。它只依赖 `HOME`，所以从 Finder / Dock 启动也能找到。
- **设置都在数据库里**(ADR 0011):设置页里的一切都由技能库存进数据库的 `config` 表，只认这里，不读环境变量，也不用系统钥匙串或设置文件。
  - 应用设置：检查更新、通用与 Agent 的显示勾选，以及这台机器是否打开过 app(第一次打开时带用户入库已有的技能)。经 `Library.AppSettings` / `SetAppSettings` 整组读写，数据库里没有的项取默认值，加设置项就是给 `Settings` 加字段。随推送、拉回走，拉回后换成拉回的那份库里的，立即生效(界面语言随之切换);这台机器已经打开过 app 的记录保留。
  - GitHub 令牌(`Library.GitHubToken` / `SetGitHubToken`):随推送、拉回走，拉回后换成拉回的那个。没填时匿名访问，受限时再用 `gh` 的登录。
  - AI 设置(`Library.AISettings` / `SetAISettings`):接口类型(OpenAI 兼容或 Anthropic)、服务地址、API Key、模型，以及请求头(一行一个「名字: 值」)与请求体(合并进每个请求的 JSON 对象，用来设置思考深度这类参数),随推送、拉回走。「测试连接」(`Library.TestAISettings`)用表单上还没保存的那一组发一条很短的消息。
  - 自动翻译技能描述：AI 分区里的开关，是应用设置，默认打开。开着且填了模型时，主界面把快照里还没有界面语言译文的描述每 8 个一批交给 `Library.TranslateDescriptions`,翻完一批重读一次;技能库跳过已经是界面语言的描述。失败时提示一次，到 AI 设置改了或下次打开 app 之前不再自动翻译。
  - 同步设置(`Library.SyncSettings` / `SetSyncSettings`):只属于这台机器，推送出去的库里不带，拉回时保留本机的。缺存储桶或密钥时同步报未配置。
  - 密钥以明文存在数据库里：数据库所在目录建成 0700,打开时把数据库文件(连同 -wal、-shm)改成 0600;数据库开着 `secure_delete`,清空或换掉的值在文件里清零。拉回后 Go 端发 `settings-reloaded` 事件，开着的设置页随之重读。
- **自动检查更新**：默认打开、每天。Go 端每分钟看一次是否到了间隔（以技能库里记下的检查时间为准，从未检查过的技能从入库时算起，手动检查也算）；“只在打开时”是启动应用、从菜单栏或 Dock 重新打开窗口时各检查一次。只检查非本地目录来源的集合，不发系统通知；检查完更新 Dock 角标，并发 `updates-checked` 事件让前端重读。自动检查和在 skills.sh 上给未纳管技能找来源都要读来源，两件事轮流进行、不同时跑(手动检查更新不用等):启动时正在自动检查的话，未纳管技能行里的"来自 …"要等检查做完才出现;反过来，正在找来源时到了检查时间，自动检查推迟到找完再做。各自做完后立即把空闲内存还给系统。
- **Dock 角标**：计入角标的技能数，按技能库给出的 `UpdateCheck.Pending`(有新版本且没跳过、来源里已删除且没选继续保留、推测出改名;本地目录来源、跳过的改动、新技能不计入),和左栏"更新"的计数一致；前端每次重读快照后经 `AppService.RefreshBadge` 重算。只在 macOS 上显示。
- **卸载 Mechbox**:设置页最后一个分区。弹窗先现查各处安装的状态，写明会删什么(技能库，连同设置页里的设置、GitHub 令牌、AI 设置与同步设置;应用本身);配置了同步时提醒可以先推送(「先去同步…」打开同步弹窗),没配置时写明无法恢复。已安装的技能文件夹按全局、各项目分开计数，三选一：保留(默认，Agent 照常使用)、移到废纸篓但保留被改过的几处、全部移到废纸篓;被改过的逐处列出。确认后移文件夹(已经不在的、在不在这台机器上的项目里的跳过),中途失败时数据库不动，重试时跳过已经移走的。然后退出，技能库关上以后再删数据库(目录空了连目录一起删)、`~/Library` 下 WebKit、Caches、HTTPStorages、Saved Application State、Preferences 里这个应用的数据，最后把 `.app` 移到废纸篓，移不动时在 Finder 中选中它。S3 上的库不动。不在 `.app` 里运行(如 `go build` 出来的)时不动可执行文件;Windows / Linux 上:
  - 退出后只删数据库，应用本身和 WebView 的数据不动，弹窗里写明应用要用系统的方式卸载。
  - Windows 上文件夹移到回收站，弹窗里说「回收站 / Recycle Bin」;WSL 发行版里的文件夹(`\\wsl.localhost\...`)进不了 Windows 回收站，经 `wsl.exe` 按 freedesktop 规范移进那个发行版的 `~/.local/share/Trash`。
  - Linux 上文件夹按 freedesktop 规范移进 `$XDG_DATA_HOME/Trash`(默认 `~/.local/share/Trash`);和家目录不在同一个文件系统上时，放进那个卷顶层的 `.Trash/$uid` 或 `.Trash-$uid`。弹窗里中文说「回收站」,英文说 Trash。
  - 进不了回收站时报错，那一处留在原处、不直接删除;弹窗提示可以改选保留后重试。
  - server 模式下只删数据库，文件夹直接删除。
- **WSL 发行版里的 Agent**:Windows 上装了 WSL 时，设置页「通用」里选各 Agent 的全局目录在 Windows 本机(默认)还是某个 WSL 发行版，由技能库存进数据库(`Library.SetWSLDistro`,只属于这台机器，推送不带、拉回保留),启动时取出(`Library.WSLDistro`)再交给技能库。选了发行版后，全局目录换成发行版主目录下的(`\\wsl.localhost\<发行版>\home\<用户>\...`,界面上缩写成 `~`),之前装在 Windows 本机全局目录里的技能留在原处、不再管;数据库、令牌、同步设置与自动检查都只有一份，不随它变。改选时打不开发行版就不保存，报错说明原因;启动时打不开，技能库先用 Windows 本机的全局目录，主界面弹窗说明原因，可以再试或改回 Windows 本机(`AppService.WSLDistroError`、`RetryWSLDistro`);关掉弹窗时提示现在用的是 Windows 本机的全局目录，设置页这一项下面也一直写明，并可以再试一次。WSL 没有响应时，启动最多等 30 秒就按打不开处理。卸载 Mechbox 时要移走的文件夹里有发行版里的，弹窗写明它们进那个发行版的回收站、怎么找回。不论选的是哪里，登记在发行版里的项目、发行版里的本地目录来源也都按发行版里的规则读写(符号链接、可执行权限经 `wsl.exe` 在发行版里处理，见技能库的包说明)。
- **界面语言**：设置页「通用」里选跟随系统(默认)、简体中文或 English,存在数据库的应用设置里(跟随系统时不写)。跟随系统时由 Go 端判断系统语言(`AppService.Language`):macOS 读系统设置里排第一的首选语言(`[NSLocale preferredLanguages]`,不用 WebView 的 `navigator.language`,它跟随 app bundle 声明的语言),其他平台与 server 模式读 `LC_ALL` / `LC_MESSAGES` / `LANG`;首选中文(含繁体)时用中文，其余用英文。前端等 Go 端给出语言再渲染，改了设置整个界面立即切换，菜单栏图标的菜单与 macOS 顶部菜单栏同时换文字。系统控件(目录选择框的按钮、输入框的右键菜单等)跟随系统语言，不跟随这里的选择;`Info.plist` 声明了 en 与 zh-Hans 两种本地化，系统控件才会按系统语言显示中文。
- **关闭窗口**：“关闭窗口后留在菜单栏”打开（默认）时，关闭窗口只是隐藏，Dock 图标和角标仍在，菜单栏出现一个入口（打开 / 退出）；点它或 Dock 图标重新打开窗口，入口随之消失。关掉时关闭窗口就退出。
- **单实例**：同一时间只运行一个实例。再次启动时，新进程直接退出，把已有窗口带到前台（最小化了也会恢复）。单实例检查早于打开技能库，第二个进程不会碰库文件。

### 界面文案

界面上看得到的文字(JSX 文本、`title` / `placeholder` / `aria-label` 等属性、toast、弹窗、错误文案)都写进 `frontend/src/lib/i18n/` 的两份文案文件，新增文案时中英一起写：`zh.tsx` 是唯一来源，按界面区域分组;`en.tsx` 照它的结构翻译，`satisfies Messages` 让漏翻、参数不对的条目在 `tsc` 里报出。

- 组件里用 `useT()` 取当前语言的文案;组件外的函数(`model.ts`、`features/` 里的写操作流程等)用 `messages()`。
- 带变量的句子写成函数，整句交给文案文件：不要把半句话当参数传，也不要在组件里拼接两句文案(英文语序不同，句子之间还要空格)。带格式的句子(如加粗的名字)让函数返回 ReactNode。
- 英文的单复数、列表(`Intl.ListFormat`)在 `en.tsx` 里处理;中文列表照旧用顿号。日期统一经 `formatDate`,数字的 `toLocaleString` 显式传语言。
- 英文用词：术语表(`CONTEXT.md`)里有的概念用术语表的英文名。
- 按平台换说法的文案(如卸载时的废纸篓 / 回收站)在文案函数里调 `lib/platform.ts` 的 `platform()`,组件不传平台。
- Go 这边的菜单文字在 `menu.go` 的 `nativeLabels`,同样中英两份。

### 给前端加一个技能库调用

1. 在 `library_methods.go` 里加一个方法，签名沿用技能库的：`ctx` 在前，返回 `(T, error)`。转发时经 `settle` 包一层：`return settle(s.lib.X(ctx))(ctx)`。前端取消调用后 Go 端若仍返回错误，Wails 会把它报成未处理的 rejection，`settle` 负责把这种错误吞掉。
2. 重新生成绑定。`wails3 dev` / `build` 会自动生成；也可以手动运行 `wails3 generate bindings -clean=true -ts -i`。生成的文件要提交。
3. 前端从 `@bindings/cmd/desktop` 导入 `LibraryService`，类型从 `@bindings/internal/library` 导入。读库里现有状态的只读调用写成 `lib/library.ts` 里的查询(TanStack Query 的 `queryOptions`,经 `wails` 把查询的 `signal` 接到可取消的调用上),组件里用 `useQuery` 取;快照用 `useSnapshot()`,不经 props 传。内容只由 key 决定、或来自技能库以外的查询标 `meta: stable`,写操作后不重读。生成计划、入库预览这类流程里的一步会在 Go 端留下状态，不做成查询，在弹窗或流程里直接调用，关掉时 `cancel()`。写操作放进 `features/` 里对应流程的文件，经 `ui.run` 执行——它负责忙碌状态、按错误码提示，并在完成后让查询缓存失效重读(`reloadLibrary`)。

错误：Go 端所有错误都经 `library.ErrorOf` 规范成技能库错误，再编码给前端。前端从 `err.cause` 拿到 `{code, message, details}`，用 `lib/library.ts` 的 `toLibraryError` 读取。

### 界面样式

主界面的外观以 UI 原型（分支 `worktree-prototype-wails-ui` 的 `cmd/prototype-wails`，变体 A）为准，用 shadcn/ui 组件 + Tailwind 实现(ADR 0008)。

- 控件用 `components/ui/` 里的组件(Button、Badge、Switch、Dialog、Sheet、Popover、Input、NativeSelect、Segmented、Card、Notice、ListBox / ListRow、Field / Hint),不在组件外另写一套同类控件。shadcn 的组件代码复制进来后按本应用改过，改动写在各文件开头。
- 颜色、圆角、阴影用 `index.css` 里的主题(`text-foreground`、`border-border`、`rounded-tile`、`bg-glass-overlay` 等),不写一次性的色值。
- 毛玻璃来自窗口背后的 macOS 原生层，界面只用半透明白色让它透出来，档位见 `index.css`:`glass-tile`(三栏底板)、`glass-card`(摘要条与弹层里的卡片)、`glass-overlay`(抽屉、弹窗、弹层，另加 `backdrop-blur`,底下的内容糊掉而不是透出文字)。加 shadcn 组件时先把默认的不透明背景和深色遮罩换成这几档。
- 禁用的白底控件只把文字调淡，不整体降透明度，否则白色按钮会融进毛玻璃背景;蓝色主按钮禁用时降透明度。
- 按钮的 `loading` 让文字留着占位、上面盖一个转圈，按钮宽度不变;弹窗贴着窗口上部出现，内容变高时只往下长。
- 详情抽屉是非模态的 Radix Dialog,在主体区域里原地渲染、没有遮罩：抽屉开着时其他地方照常可用，点别的技能行切换、再点当前那一行关闭，Esc 或关闭按钮也能关。弹窗(`Modal`)是模态的，叠了几层时 Esc 只关最上面一层。
- `index.css` 只放工具类管不到的：页面基础样式、窗口底色(`window-backdrop`)、渲染出来的 Markdown(`.md`)与拖放中的高亮(按 `data-dragging`、`data-drop-hover` 等属性)。
- e2e 按两类钩子找元素：通用控件用 `data-slot`(`dialog-content`、`badge`、`list-row` 等)或角色(`role="switch"`、`aria-pressed`);应用自己的结构用类名(`skill-row`、`section-head`、`nav-item`、`set-row` 等)。这些类名不挂样式，改结构时保留。
