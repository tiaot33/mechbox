# 产品承诺：用户没有点头，Agent 用的技能就不变

技能是 Agent 会照着执行的指令和脚本，以用户自己的权限运行。来源里的改动本质上是供应链风险。而 Mechbox 是低频工具，用户不会守着它看来源里发生了什么。所以无论做什么功能，都要守住下面几条承诺，违反任何一条都按 bug 处理：

1. **用户什么都没点，Agent 用的内容就不会变。** 检查更新可以自动进行，但只读：不改技能的内容和版本，也不碰装出去的文件夹。
2. **每次更新都能回滚。** 回滚后，库回到更新前的版本。如果那次更新连带重新安装了装出去的地方，回滚时这些地方也一起重新安装回去。
3. **来源里删掉的技能，不会自己从库里或 Agent 里消失。** 库只把它标出来，要不要移除由用户决定。
4. **用户明确不要的东西，不会再作为待办出现**，除非来源里又有了新变化。比如入库时没选的技能、用户跳过的改动、用户回滚掉的改动，或者用户决定保留的、来源里已删除的技能。
5. **用户在装出去的文件夹里改过的内容，不会在没有明确说明的情况下被覆盖。**

产品层面的考虑见 [产品定位](../product/positioning.md) 和 [更新的产品逻辑](../product/update.md)。

## 考虑过的选项

- **像应用商店那样在后台自动更新。** 省事，但 Agent 的行为会在用户不知情时改变，出了问题也查不到是哪次变化造成的。对一个以用户权限执行脚本的东西，这个代价太大。

## 后果

- **第 2 条由回滚满足。** 每次更新留一条记录，回滚把库换回那次之前的版本，并把那次装过、磁盘上仍是那次换上的版本的地方装回去(#165)。任何新的更新功能都要连同回滚一起设计。
- **第 1、3、5 条，现有行为已经满足：**
  - 检查更新只记下结论；
  - 来源里找不到某个技能时，更新只报找不到，不删除任何东西；
  - 安装遇到已有文件夹默认不覆盖；
  - 重新安装遇到被手动改过的文件夹，默认该条失败。

  覆盖都要用户明确选择覆盖。
- **第 4 条约束以后的功能。** 现在还没有提示来源里新技能的功能，做的时候要按这条设计。
