# GitHub 令牌进数据库、随同步走；S3 同步设置只存在这台机器上

从访达或 Dock 启动的桌面端读不到 shell 里的环境变量（[ADR 0008](0008-desktop-is-wails-v3-in-process.md) 的后果），所以设置页可以填 GitHub 个人访问令牌和同步用的 S3 设置。它们存在不同的地方：

- **GitHub 令牌**存在数据库里，和库里其他内容一样随推送、拉回走。
- **Secret Access Key、Session Token** 存在系统里：macOS 存在钥匙串里，Windows 存在凭据管理器里，Linux 存在系统密钥环里（D-Bus 上的 Secret Service，如 GNOME Keyring、KWallet）。
- **服务地址、存储桶、对象名、区域、Access Key ID** 和检查更新、通用这些设置一样，存在数据库旁边的应用设置文件 `settings.json` 里。

令牌由库读写。S3 设置在应用启动时和用户保存后由桌面端交给库，库只在这次运行里持有，不写进数据库。

设置页填的只是多一个来源，环境变量照旧有效：

- 令牌没填时，库读 `GITHUB_TOKEN` / `GH_TOKEN`。
- 同步设置整组取用：填了任意一项就整组用设置页的；全部留空时才读 `SKILLS_S3_*`、`AWS_*`，不逐项拼接。

## 为什么令牌进数据库

用户换一台机器，填好 S3、拉回整个库之后，令牌也跟着回来，不用再填一遍。

- 令牌会出现在 S3 上的对象里。但存储桶是用户自己的，能读到这个对象的人本来就能读到整个库。
- 拉回时，另一台机器的令牌会盖掉本机的。同一个人通常只用一个令牌，这不会造成问题。拉回的库里没有令牌时，本机的令牌也随之变成没填，回到读环境变量。

## 为什么 S3 设置仍只在这台机器上

- 新机器得先填好 S3 才能拉回，同步了也省不掉这一步。
- 用户可能给每台机器配了不同的 Access Key。拉回时盖掉本机的设置，会让这台机器之后的推送莫名失败。

## 为什么 S3 的密钥存在系统里

`settings.json` 是明文：备份、复制目录或排查问题时把它发给别人，都会把密钥一起带出去。这三处都加密保存：macOS 钥匙串默认只有存进去的应用能直接读取，别的应用要读，得经用户在系统弹出的授权框里同意；Windows 凭据管理器按登录用户加密，只存在这台机器上，不随漫游配置文件走；Linux 的密钥环通常随登录解锁，锁着时由系统弹出解锁框。

其余几项不是秘密，Access Key ID 只是密钥的编号，所以和别的应用设置放在一起，打开文件就能看到和修改。

两项合成一个条目保存。在 macOS 上，应用的签名变了（ad-hoc 签名的应用每次构建都会变），系统会在应用第一次读取时询问是否允许，每个条目问一次；合成一个条目，用户只需确认一次。Windows 的单条凭据最多 2560 字节，Session Token 的长度 AWS 不保证，放不下时分成几条，最后才改写第一条，中途失败时旧内容仍在。

## 考虑过的选项

- **令牌也存在系统里、不随同步走**：之前的做法。换机器要再填一遍令牌；不同步的理由是令牌会出现在 S3 上的对象里，但能读到这个对象的人本来就能读到整个库，这条理由不成立。
- **S3 设置也进数据库**：省不掉新机器上填 S3 这一步，还可能盖掉这台机器自己的 Access Key，原因见上文。
- **全部存进 `settings.json`**：最简单，但密钥是明文。
- **Linux 上没有 Secret Service 时退回 `settings.json` 或只存在内存里**：前者是明文；后者退出就丢，用户以为存上了。所以没有时如实报读不到。

## 后果

- 换一台机器时，在新机器的设置页填好同步设置（或者设置环境变量），拉回后令牌随库回来。
- 不迁移之前存在系统里的令牌：升级后用户重新填一次。
- 系统里读不到时（macOS 上应用换了签名后第一次启动，用户拒绝了授权；Linux 上没在解锁框里解锁，或者没有 Secret Service——没有 D-Bus 会话、没装或没启动 GNOME Keyring / KWallet），只影响同步：设置页填过同步设置的，同步缺密钥，不能进行。打开设置页时会再读一次，读到就恢复；仍读不到时，设置页不显示同步分区的表单，免得把没读到当成没填，保存时盖掉存在系统里的内容。令牌不在系统里，GitHub 分区照常显示和保存。
- 卸载 Mechbox 时先删系统里的条目，删不掉就什么都不动，用户可以重试或跳过；令牌随数据库一起删掉。
- server 模式（端到端验证用）在各平台上都不碰钥匙串、凭据管理器或密钥环，密钥只存在进程内存里。
