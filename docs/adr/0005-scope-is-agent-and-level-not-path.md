# 作用域按 Agent 和层级记录，不按路径

作用域只有两种：某个 Agent 的全局，或者某个 Agent 加一个已登记项目。库里只记录这个身份。技能具体放进哪个目录，在安装或列出时按该 Agent 读取技能的目录推算出来。

调用方不能指定安装目录。Agent 读取技能的目录分两种情况：

- **内置 Agent**（Claude Code、Codex）：目录由 Agent 厂商决定，由产品随版本维护，用户不能修改。
- **自定义 Agent**：用户自己添加，目录由用户填写，之后也可以修改。只有用户知道这个 Agent 读哪里；填错了 Agent 读不到，由用户自己负责。

两种 Agent 的目录都按相对路径记录：全局目录相对用户主目录，所以自定义 Agent 的全局目录也必须在用户主目录下；项目目录相对已登记项目的根目录。

不按路径记录，是因为目录名由厂商决定，而且会变。比如 Codex 就把读取目录从 `.codex/skills` 换成了 `.agents/skills`。如果按路径记录，目录一变，就会出现两个问题：

- 目标列表、各项目下的目录、同步时的路径对应，还有测试，都要各自重复处理同一套路径规则。
- 以绝对路径为键的记录同步到另一台机器后，还得去猜怎么对应到新机器的用户主目录。

按身份记录，厂商换目录时只需改库里该 Agent 的一行；同一条安装记录在任何机器上都能算出正确的目录。

## 考虑过的选项

- **作用域里带路径。** 这样调用方可以装到任意位置，库就变成了一个复制工具，而不是替用户管理 Agent 读取技能的地方。另外，旧的目录名会被固化在记录里。
- **允许用户修改内置 Agent 的读取目录。** 这样作用域可能指向一个 Agent 根本不读取的地方，而内置 Agent 读哪里，产品比用户更清楚。
- **只支持内置 Agent。** 用户要等产品接入才能管理新的 Agent，而能读技能的 Agent 越来越多。
- **自定义 Agent 的全局目录可以在用户主目录之外。** 这样的目录要记成绝对路径，同步到另一台机器后可能对不上。

## 后果

- **内置 Agent 换了读取目录后，库只认新目录。** 以前装到旧目录的文件夹既不搬走也不删除；用户重新安装，就会装到新目录。
- **用户修改自定义 Agent 的目录时，选择迁不迁移。** 迁移是把已装的文件夹原样搬到新目录，保留用户在里面改过的内容；新目录里已有同名文件夹的，不覆盖、不搬，去掉这一处的安装记录，并列出来。不迁移就只改目录，旧目录里的文件夹不动，去掉这个 Agent 的安装记录。
- **多个 Agent 可以读同一个目录。** 这几个 Agent 的作用域共用一个文件夹：装到其中一个，其他几个也算已装；从其中一个卸载，文件夹就删掉，这几个 Agent 都不再算已装。
- **自定义 Agent 离开或删除时，不动其他 Agent 还在读的文件夹。** 改目录时，旧目录里还有其他 Agent 在读的文件夹，迁移是原样复制到新目录，不迁移就什么都不做；旧目录里的文件夹都留给还在读的 Agent，安装记录也转给它们。删除自定义 Agent 时，即使用户选了一并删除文件夹，这些文件夹也保留，确认时告诉用户哪些文件夹因为还有哪些 Agent 在用而不删。否则用户只是动了一个自定义 Agent，其他 Agent 的技能却跟着没了。
- **库从不创建作用域的根目录。** 全局作用域的根目录是用户主目录，项目作用域的根目录是已登记项目的路径；库只会创建根目录下 Agent 读取技能的那一级目录。根目录不存在，说明这个项目不在当前机器上，可能是从别的机器同步过来的、被移动过，或者在未挂载的磁盘上。这种情况下安装会失败，而不是凭空建出整条路径。
- **同步到另一台机器后，只需把已登记项目对应到本机路径。** 安装记录和自定义 Agent 本身不用改。
