# 作用域按 Agent 和层级记录，不按路径

作用域只有两种：某个 Agent 的全局，或者某个 Agent 加一个已登记项目。库里记录的是这个身份。调用方不能指定安装目录：新装的技能放进这个 Agent 在这一层级的第 1 个技能目录。

所有 Agent 都存在数据库的一张表里，地位相同。应用按 skills CLI 的目录表收录 Agent，放进候选池；用户从候选池添加，或自己填一个添加。每个 Agent 的名称、技能目录、检测目录都能改，都能移回候选池。应用打开数据库、拉回别的库时，只插入它收录的、表里还没有的 Agent，从不改写已有的行。

目录都按相对路径记录：全局目录相对用户主目录，所以 Agent 的全局目录必须在用户主目录下；项目目录相对已登记项目的根目录。一个 Agent 在一个层级可以有几个技能目录，第 1 个装新技能，其余是附加目录。

一处安装的记录可以带上它实际所在的技能目录，也是相对路径；为空时就是这个 Agent 这一层级的第 1 个目录。只有从附加目录原地入库的技能才需要记下目录：库不搬动用户已有的文件夹，又要在巡检、更新、卸载时找到它。

不按绝对路径记录，是因为目录名由厂商决定，而且会变。比如 Codex 就把读取目录从 `.codex/skills` 换成了 `.agents/skills`。如果按绝对路径记录，目录一变，就会出现两个问题：

- 目标列表、各项目下的目录、同步时的路径对应，还有测试，都要各自重复处理同一套路径规则。
- 以绝对路径为键的记录同步到另一台机器后，还得去猜怎么对应到新机器的用户主目录。

按身份加相对目录记录，Agent 换目录时只需改表里该 Agent 的一行；同一条安装记录在任何机器上都能算出正确的文件夹。

## 考虑过的选项

- **作用域里带路径，调用方指定装到哪里。** 这样库就变成了一个复制工具，而不是替用户管理 Agent 读取技能的地方。新装的技能也不让用户在一个 Agent 的几个目录之间挑。
- **收录的 Agent 由应用维护，用户不能改。** 以前内置的 Claude Code、Codex 就是这样。可是用户用环境变量改过 Agent 的配置目录（如 `CLAUDE_CONFIG_DIR`）时，库不读环境变量，只能看着目录不对。收录了七十多个 Agent 以后，这种情况只会更多。
- **应用升级时按新版本改写表里已有的 Agent。** 用户改过的目录会被盖掉；拉回别的版本推上来的库时，Agent 的目录也会跟着变。
- **只记一个技能目录。** 一个 Agent 读几个目录时（如 Cursor 全局既读 `~/.agents/skills` 也读 `~/.cursor/skills`），扫不到另一个目录里已有的技能；把那里的技能原地入库后，巡检、更新去第一个目录找，会误报文件夹不在了。
- **Agent 的全局目录可以在用户主目录之外。** 这样的目录要记成绝对路径，同步到另一台机器后可能对不上。

## 后果

- **一个技能在一个 Agent 的一个作用域里只算一处。** 一处安装是「全局或哪个项目 + 技能目录 + 文件夹」，已添加的 Agent 里目录列表有这个目录的都读得到它。每个 Agent 只认一处：自己有记录的认记录那一处；没有的，按它的目录顺序认第一个装着这个技能的目录。
- **多个 Agent 可以读同一个目录。** 认同一处的几个 Agent 共用一个文件夹：装到其中一个，其他几个也算已装；从其中一个卸载，文件夹就删掉，这几个 Agent 都不再算已装。往会让别的 Agent 读到两份的目录安装时照装，事先提示。
- **改 Agent 的目录时，按每处安装原来所在的目录处理。** 这个目录还在新列表里的，磁盘不动。不在了的，用户选迁不迁移：迁移是把文件夹原样搬到新的第 1 个目录，保留用户在里面改过的内容；新目录里已有同名文件夹的，不覆盖、不搬，去掉这一处的安装记录，并列出来。不迁移就文件夹不动，去掉这一处的安装记录。
- **改目录或移除 Agent 时，不动其他 Agent 还在读的文件夹。** 改目录时，旧目录里还有其他已添加 Agent 在读的文件夹，迁移是原样复制到新目录，不迁移就什么都不做；旧文件夹都留给还在读的 Agent，安装记录也转给它们。移除 Agent 时，即使用户选了一并删除文件夹，这些文件夹也保留，确认时告诉用户哪些文件夹因为还有哪些 Agent 在用而不删。否则用户只是动了一个 Agent，其他 Agent 的技能却跟着没了。
- **库从不创建作用域的根目录。** 全局作用域的根目录是用户主目录，项目作用域的根目录是已登记项目的路径；库只会创建根目录下 Agent 读取技能的那一级目录。根目录不存在，说明这个项目不在当前机器上，可能是从别的机器同步过来的、被移动过，或者在未挂载的磁盘上。这种情况下安装会失败，而不是凭空建出整条路径。
- **同步到另一台机器后，只需把已登记项目对应到本机路径。** 安装记录和 Agent 本身不用改。
