# 组安装是一个持续的选择

组不只是一个标签。用户可以把整个组安装到某个作用域，也可以从那里整个卸载。组安装记录的是"这个组适用于这个作用域"这个选择，而不是安装当时装上了哪些技能：

- **组员变化会跟着生效。** 之后加入组的技能，会装到这个组已经安装到的每个作用域。把技能移出组时，由用户选择：保留它（改为直接安装），或者一并卸载。
- **冲突只跳过有冲突的成员。** 安装组时，某个成员可能遇到冲突：目标位置已被占用、存在库里没有记录的同名文件夹，或者和组内另一个成员同名。这时只跳过这些成员并逐个报告，其余成员照常安装。组安装本身仍然成立，冲突解决后再装一次这个组就能补齐。一个成员有冲突，不应该否决"这个组适用于这里"的整体意图。
- **加入成员时不提供覆盖选项。** 这个开关会同时作用于该组安装到的所有作用域，影响面太大。如果要覆盖某一处，先查看安装计划，再只对那个作用域带覆盖选项重新安装这个组。

同一个技能在同一个作用域里，可以既被直接安装，又随某个组安装，磁盘上只有一个文件夹。卸载其中一种，只要另一种还在，技能就保留；两种都撤销后，文件夹才会删除。安装一个已经装好的技能，只会补记这次选择，永远不会覆盖原来的文件夹；要把文件夹更新到当前版本，需要重新安装。

组和集合互不相关：集合按来源自动形成，组由用户按场景跨来源挑选。组是扁平的，不能嵌套。组引用的是技能本身，不固定到某个版本。
