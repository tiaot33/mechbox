# 库的数据集中存在一个数据库里

库的全部内容都存在一个 SQLite 数据库里，包括每个技能各版本的文件，以及集合、组、安装记录和已登记项目。Agent 目录里的技能文件夹都是安装时从库里写出去的。之后在这些文件夹里做的修改不会进库：库只拿它们和库里的版本比对。

我们没有采用"技能以文件夹形式放在某个目录，元数据另外存"的做法，原因有三个：

- **一次操作常常涉及多个技能**，比如安装一个组、同步整个库。数据放在一个数据库里，就能用事务保证要么全部成功，要么全部不生效。
- **同步只需推拉一个文件**，不用逐个比对大量零散文件。同步不要求实时，所以以整个库为单位没有额外代价。
- **版本历史必须是库自己的数据**（见 [0002](0002-versions-store-each-file-once.md)）。本地来源的技能没有远端，历史无处可依赖。

Agent 只认目录里的文件夹，不读数据库。安装时，库把完整的技能文件夹写进该 Agent 在这个作用域读取的目录，包括 `scripts/` 等资源文件，以及文件的可执行权限。安装成功只说明文件已经放好；Agent 会不会发现、选用这个技能，由 Agent 自己决定。

## 后果

- 在 Agent 目录里直接改技能文件，改动不会进库。巡检会把它报告为被手动改过，重新安装时可以选择覆盖。
- 本地来源的技能要改内容，应该在来源目录里改，再更新进库。
