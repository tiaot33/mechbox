# 每个版本完整保存，相同内容的文件只存一份

每次入库或更新，都为这个技能保存一个完整版本。版本记录技能根目录下每个文件的三项信息：相对路径（如 `scripts/helper.py`）、内容指纹、是否可执行。文件内容按指纹存放，内容相同的文件在整个库里只存一份。目录结构隐含在路径里，不单独记录。

历史是库自己的数据，不依赖远端 Git，因为同步以整个库为单位，本地来源的技能也没有远端。之所以按单个文件而不是按整个目录存内容，是为了同时做到两件事：

- **多存一个版本，只增加真正改动过的文件。** 库和同步文件不会随着历史变长而膨胀。
- **比较两个版本，只需对比两份文件清单。** 路径相同而指纹不同，说明文件被修改；路径只出现在一边，说明文件被新增或删除。

我们没有采用 Git 那种逐层的目录树对象，因为技能的规模很小，一份平铺的路径清单就够用。

## 后果

- 无法表示空目录，所以不支持空目录。
- 同一份文件内容可能被多个版本共用，只有当所有版本都不再引用它时才能回收。回收目前还没有实现。
- `SKILL.md` 里的描述属于版本，不属于技能。它随文件一起变化，查看任何一个版本时，描述都和当时的文件对得上。
