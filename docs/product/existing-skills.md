# Agent 目录里已有技能的产品逻辑

本文是 Agent 目录里未纳管技能的产品设计（GitHub issue #183，自动纳入规则按 #386 修订）：不是库装的能入库，库装出去又被改过的能用这份修改更新库里的技能。

- 底线承诺见 [ADR 0010](../adr/0010-product-promises.md)，产品定位见 [positioning.md](positioning.md)，更新/跳过/回滚见 [update.md](update.md)。
- 核心判定见 [ADR 0014](../adr/0014-existing-skills-recognized-by-content.md)（按内容识别、自动纳入与三类例外、同名异内容不合并）和 [ADR 0012](../adr/0012-symlinks-become-own-folders-after-takeover.md)（接管后符号链接何时换成独立文件夹）。

对应三个核心诉求：**把已有的接过去**（首次打开、新项目、新机器）、**看清 Agent 实际看到什么**（Agent 表现异常时排查）、**在哪改都算数**（用户或 Agent 直接在目录里改技能）。

## 把已有的接过去

**目标**：接管已有技能时磁盘上一个字节都不改，Agent 在各项目里的表现与之前完全一致。

### 自动纳入与三类默认不接
- **与库里任意一版内容一致**：自动纳入管理、补记安装，不再出现在未纳管列表和整批入库确认里；和作者最新版一致但库里尚无该版时，走集合的更新计划（详规见 [ADR 0014](../adr/0014-existing-skills-recognized-by-content.md)）。
- **三类例外既不自动纳入，也不在入库确认里默认勾选**（照常列出并标明原因，用户手动勾上时写明代价）：
  - **已提交进项目 git 仓库的技能**：归项目团队版本控制管，勾上时写清后续在 app 里更新会改动仓库里的文件；
  - **登记在项目 `skills-lock.json` 里的技能**：`npx skills` 写下的团队约定配置（即便文件本身未进 git），同样归项目仓库管；
  - **软链接指向 Agent 目录以外（如用户本地工作目录）的技能**：写明指向路径，勾上时写清后续更新会换成独立副本，在工作目录里改不再同步生效。

### 引导时机与确认界面
- **入口跟着列表走，不记「问过没有」**：在这台机器第一次打开 app 时带用户看各 Agent 全局目录的未纳管技能（注明「项目里的技能，登记项目时再接」），登记项目时带看该项目；之后在作用域「不在技能库里」标题上、项目页顶部都能批量入库，也可逐个入库。
- **未勾选的不催**：不算待办、不计角标、不弹窗，只在作用域和项目摘要写有几个未纳管技能。
- **按作者分组，默认全选（除上述三类）**：确认列表按认出的来源分组（如 `matt/skills · 5 个`），认不出的单独一组，支持整组勾选/取消。
- **话按分量说**：第一句写清「磁盘上什么都不改，Agent 用的和现在一样」，接着说明交给 app 管的代价（之后若再用命令行工具更新：追上作者新版 app 会认出并走更新，改成别的会报被手动改过）；仓库提醒、外部软链接提醒、同名冲突只在触发时出现。

### 冲突、符号链接与来源追踪
- **同名不同内容不合并**：跨作用域同名且内容不同时单列冲突，默认入库最近修改的那份，其余留作未纳管；库里已有同作者同名但内容对不上也不合并，用户可清空来源作为无来源技能入库。内容完全一致的多处入库成一个技能、各处记为安装。
- **Agent 目录间的符号链接一并记下**：多个 Agent 目录经软链接指向同一真实文件夹时，任一处入库就一并记为装在各处（确认里写明哪几处）；仅内容相同却是独立文件夹的不连带，归项目仓库管的也不连带。链接在入库时不动，首次写入或删源目录时才换成独立副本（见 [ADR 0012](../adr/0012-symlinks-become-own-folders-after-takeover.md)）。
- **来源确认与容错**：来源按 [ADR 0014](../adr/0014-existing-skills-recognized-by-content.md) 优先级识别，确认前展示以后跟谁检查更新，支持改链接或清空。读来源等待时显示在等什么；单项失败不拖累其余，单列出来重试、改链接或清空，不悄悄当成无来源。
- **接管后照常跟着作者走**（有来源的技能入库后与作者版本的关系）：
  - **和作者最新版一致**：就是作者这一版。
  - **不一致，但 `npx skills` 哈希对得上磁盘**：作者旧版，照常报有更新。
  - **不一致，但 `npx skills` 哈希等于作者最新版**：当作用户在该版上的修改，首次不报更新；等作者再改才提示「更新会换掉你的修改」且默认不勾。
  - **不一致，且无哈希或对不上**：先报一次有新版（写清会换掉修改、默认不勾），跳过后直到作者再改。
  - **无来源**：按「作者就是用户自己」处理。

## 看清 Agent 实际看到什么

- **按作用域列全**：已纳管与未纳管技能放在一起，一眼区分。
- **同名说出后果**：直接写清在该 Agent 里会怎样（Claude Code 全局生效，Codex 两份都出现），不只标「同名」。
- **只看、不代删**：非库装的未纳管技能只提供在 Finder 中显示。

## 在哪改都算数

- **留下目录修改就是一次更新**：确认时列出该技能的其他安装处，默认一起同步（用户改过的地方默认不勾）；留记录、能回滚。
- **改了作者的技能照常跟作者走**：有没有新版只看「作者从你改的那一版之后有没有改过」；有新版时写清「更新会换掉你的修改」且默认不勾，不想用就跳过，不另造「不再跟随」状态。
- **无来源技能，作者就是用户自己**：不进更新页、不计角标，只提供用目录里的修改更新（等同本地目录来源的「重新读取」）。

## 怎么判断做对了

| 给用户的任务 | 怎样算通过 |
| --- | --- |
| 「第一次打开 app，把你在用的技能都交给它管。」 | 一次确认完成；之后 Agent 表现不变，也能把这些技能装到另一个项目 |
| 「库里已有技能 X，Claude Code 全局目录里有一份一模一样的。」 | 不用操作，自动记为 X 的一处安装，巡检正常，不出现在未纳管和入库确认里 |
| 「Claude Code 在这个项目里有哪些技能？」 | 列得全，包括未纳管技能 |
| 「pdf 在这个项目里表现得不像你装的版本。」 | 能发现全局有一个同名的，并知道哪个生效 |
| 「换台机器，把你的技能都带过去。」 | 原来手动拷的技能也带过去了 |
| 「你在 Claude Code 目录里改了一个技能，让 Codex 也用上。」 | 一次确认完成 |
| 「你改过 pdf 里的一句话，作者又发了新版。」 | 能看出更新会换掉你的修改；不想要就跳过，角标消失 |

## 留到实现时定的

- 首次打开/登记项目入库引导屏、作用域与项目页批量入库、单个入库、用目录修改更新等按钮和提示的最终文案。

## 不在范围内

- 插件里的技能、企业托管目录和 Codex 的 ADMIN / SYSTEM 技能。
- 未登记的项目；自动监视 Agent 目录变化并自动入库/更新。
- 推算完整的客户端生效规则（插件启用、frontmatter 关闭自动调用等），只标出同名。
- 新机器首次打开时把库里技能装到本机（另行设计时要和这里的入库引导放在一处，不先后弹两次）。

## 术语

已定术语见 [CONTEXT.md](../../CONTEXT.md)（未纳管技能、入库、作用域、已登记项目、集合、检查更新、更新计划、更新、跳过、回滚、重新安装）。「把已有的接过去」「作者那边有没有改过」仅作本文描述；「用目录里的修改更新」是更新的一种，不另起概念。
