# 产品定位

本文记录产品层面的判断：用户是谁、什么时候用这个工具，以及这对桌面端意味着什么。术语以 [CONTEXT.md](../../CONTEXT.md) 为准；用户操作流程见 [ADR 0009](../adr/0009-user-flow-fetch-then-install.md)；任何功能都要守住的承诺见 [ADR 0010](../adr/0010-product-promises.md)。

## 用户与使用频率

用户是用 Claude Code、Codex 写代码的开发者。他们从几个地方收集技能：GitHub 上的作者、团队自己的仓库、自己的本地目录，再装到全局和几个项目里。

技能管理器是**低频工具**。用户每天打开的是 Agent，不是这个 app。会打开它，通常是这几种时刻：

1. **要加新技能**：看到别人推荐，或者在市场上搜到。
2. **新项目、新机器**：要把常用的技能装过去。
3. **Agent 表现怪了**：想知道是不是某个技能变了，或者想退回去。
4. **听说作者发了新东西**：比如在社交媒体或群里看到。

## 对桌面端的含义

- **不能指望用户主动来检查。** 有新内容时，提示要等在用户下次打开 app 就能看到的地方，比如 Dock 角标、侧边栏计数。
- **不打扰。** 低频工具弹系统通知很容易惹人烦。默认只显示角标，系统通知由用户自己开启。
- **排查是一等场景。** 上面第 3 种时刻，用户不是来更新的，而是来排查和回滚的。界面要能看出一个技能最近有没有变过、哪天变的、为什么变。

## 技能是供应链

技能是 Agent 会照着执行的指令和脚本，以用户自己的权限运行。来源里的改动本质上是供应链风险，所以：

- **审阅要回答「敢不敢让 Agent 用它」，而不只是「哪些文件变了」。** 先标出风险（新增或改动的脚本、新增的可执行文件），再给出作者的意图（GitHub 来源的提交说明），最后才是文件差异。
- **回滚是安全网。** 用户知道可以回滚，就不必每次都逐行审阅。审阅负担和回滚能力此消彼长。
- **用户对不同来源的信任不同。** 对团队自己的仓库，看一眼摘要就会全部更新；对陌生作者的仓库，会想逐个看。

## 用户心里的单位

- **用户跟随的是作者的那一套技能**，不是仓库地址，更不是单个技能。
- **用户说「更新」，期待的是 Agent 用上新版**，不只是库里有了新版。
- **本地目录作为来源时，作者就是用户自己。** 这时用户要的是快，审阅反而多余。

这几点在更新上的展开见 [更新的产品逻辑](update.md)。
